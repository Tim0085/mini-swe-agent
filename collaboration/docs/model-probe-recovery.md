# 模型验证状态与失败恢复

## 背景与目标

原配置验证成功后仍显示未验证；授权提示位于页面顶部；一次验证后页面丢失预览参数，失败后无法直接重试。本次保持已有浅色界面和依赖，修复验证流程，不自动调用真实模型或重启正式后台。

## 实现与规则

- 原配置和自建模型读取持久化测试记录；显示结果、时间以及配置是否仍匹配。兼容已有 passed/failed 记录，不把 HTTP 失败说成模型不支持工具调用。
- 新测试记录保存配置指纹、请求编号及后台会话标识。后台重启后，遗留 running 记录只读呈现为未完成，不改写历史、不自动重跑。旧成功记录可直接恢复显示；没有配置指纹的旧记录不能声称当前配置已验证。
- 新增鉴权接口 `GET /api/profiles/{profile_id}/test/{request_id}`；查询不会调用模型。既有 POST 保持同步与幂等，重复请求编号返回原记录。
- 浏览器保留正在验证的请求编号，刷新后查询原请求。暂时无法确认时保留“查询上次结果”，不创建新的付费请求。完成后提供“重新验证”，重新预览、重新勾选授权并使用新编号。
- 未勾选、预览失败和调用失败就地提示；运行时显示等待时间。关闭面板不取消已经发出的模型请求。
- 列表优先显示实际模型 ID；预览区分别显示协议、请求地址、实际 ID、内部路由名称和生成参数。保留现有 openai/ 内部前缀配置；实际验证请求仍去掉这一层前缀，不根据品牌切换协议。
- 保存脱敏且限长的服务错误码和原因；分别标记接口、鉴权、参数、限流、上游、超时、连接、工具响应、计价用量和预算问题。未知费用不当作零费用。

## 验收与限制

本地 HTTP 服务验证 404/422/502、错误脱敏、查询不重发、显式重试、超时、实际模型 ID、旧原配置成功记录、密钥变化和后台重启恢复。浏览器验证授权就地提示、失败重试、验证中刷新、成功状态、桌面和 390px 窄窗口。

证据在 `collaboration/artifacts/2026-09-20/probe-recovery/`，隔离状态留在 `.local/webui/implementation-20260920/`，pytest 状态在 `.local/webui/test-runs/`。不新增依赖，不下载镜像，不修改正式密钥，不调用外部模型。真实 Grok 的原因尚未确认，需经用户授权后使用新版诊断信息核对；普通聊天成功不代表工具验证或另一协议可用。

正式后台切换需用户确认；现有浏览器不接管、不强制刷新。
