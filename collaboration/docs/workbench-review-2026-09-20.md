# 工作台整体复盘与评测界面改进

## 背景与目标

用户无法从“未解决”判断具体原因；模型对比页筛选占据主要空间，明细需要离开比较页寻找。近期还出现 Docker 本机启动错误、费用未知后可点击继续，以及 Responses 回复被显示为原始 JSON。目标是保留现有白灰蓝界面和技术栈，让比较有依据、异常能停止、结果易读。

## 本轮调整

| 问题 | 调整 | 验收依据 |
| --- | --- | --- |
| 比较页没有清晰主次 | 紧凑工具栏，模型选择折叠；主要展示共同题集、分母、逐题矩阵 | 桌面与 390px 窄窗口截图 |
| 默认全选所有条件，容易没有共同题目 | 优先选择有共同题目且模型不同的两个条件组，再按共同有效题数选择；允许手动重新选择，不合并不同配置 | 结果索引测试与实际浏览器 |
| 未解决缺少依据 | 概览直接显示修复/回归测试数量；矩阵点击后同页对照各模型测试、失败测试名称、费用、时间与任务入口 | 真实 Astropy 报告 0/2、644/644 核对 |
| 历史条件不清楚 | 在模型旁显示连接和条件编号，参数和口径集中折叠查看；无共同题集不显示解决率排名 | 数据与无共同题集检查 |
| 窄屏只能看见一个模型列 | 手机按题目纵向排列各模型结果，保留全部模型与费用信息 | 390px 检查，无页面溢出 |
| 快速切换比较可能显示过期请求 | 增加比较请求序号，忽略过期返回；失败就地提示并隐藏过期成绩 | 静态检查及浏览器交互 |
| Docker 启动错误被当作普通命令失败 | 工作台容器启动、执行与清理统一使用隐藏子进程；识别 Windows 致命退出码并结束求解，阻止后续模型请求 | 原生子进程退出码测试；真实单题验收 |
| 系统错误弹窗打断工作 | 仅在工作台自有 worker 设置错误模式，由退出码和日志报告启动故障，不接管 Docker Desktop | 不改系统全局设置 |
| 费用未知仍显示可继续 | 队列和实验禁用继续入口，后端在恢复状态前拒绝并说明核对账单/结束批次 | 状态不改变和不新建任务的测试 |
| 模型回复显示原始数组 | 递归展开 Responses 文本块，过滤工具结构；保留命令独立区域 | 浏览器确定性文本样例 |

## 指标边界

- 保留官方 resolved 判定，不用测试通过比例替代解决率。两份 Astropy-13236 补丁均未满足两项关键测试，不改写旧成绩。
- 历史比较采用共同有效题集；实验使用固定题集的首轮结果。重新求解不替换首轮。
- 准备、求解、评测异常不显示为“未解决”；未知费用不按零计。不同服务与执行条件仍独立分组。
- Docker 退出码拦截和隐藏启动是针对已发现故障的改进，不能据此断言 Windows 初始化失败的系统根因已被彻底消除。

## 后续仍需保留的边界

- 中转断线、服务参数支持与实际扣费属于外部服务行为；界面应提供诊断，不静默重试。
- 旧任务不补造缺失的运行条件；较少题目的结果不能称为全量模型排名。
- 费用未知的旧批次不清除保护标记；如将来增加账单核对恢复，需要明确设计对账来源和审计记录。
- 未下载大镜像、未修改 Docker Desktop 或 Windows 全局设置。真实结果只说明本次验收，不保证系统故障永不再现。
