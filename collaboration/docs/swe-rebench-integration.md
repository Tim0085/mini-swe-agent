## 使用方法

1. 刷新工作台，进入“实例库”，在题集选择中选 **SWE-rebench 经典榜单**。
2. 正式目录已同步时可直接浏览、搜索、跨页选题；每页默认仍为 8 题。同步目录只保存公开题目信息，不拉取镜像。
3. 点击题目查看描述；`_interface` 题目附带的必需接口会同时显示并提供给模型。勾选题目后可缓存题目、下载环境、求解或评测已有补丁。
4. 未缓存资料与缺失镜像仍分别授权。Docker 不可用时显示“无法检查”，不会视为镜像未下载。
5. 求解成功提交后按选项自动评测本次新补丁；也可选择已有补丁单独评测。预算、命令确认、暂停和恢复规则沿用现有工作台。
6. 在评测中心筛选 SWE-rebench 后查看解决率、关键测试与模型对比。选择“全部数据集”且混有 SWE-bench 时，保留计数和费用，解决率显示“—”；比较前需选单一题集。

切换题集会清除当前输入中不再适用的题号、补丁、预览与下载／自动执行授权；刷新保留非敏感草稿。旧任务和历史不会被改写。

## 实现与关键规则

- `benchmarks.py` 提供统一注册表、API 类型校验和基准快照；四个页面选择器统一读取 `GET /api/benchmarks`。
- `rebench_data.py` 从固定提交读取约 4.86 MB 的数据文件，校验大小、SHA-256 和题数。同步仅投影公开列；单题缓存只保存选定行。传输文件只驻留内存，不在正式目录旁保留全量标准答案文件。每次同步或获取未缓存题目都可能重新读取这个小文件，缓存题目再次使用不联网。
- 缓存路径为 `.local/webui/datasets/rebench-34d5a588/<instance>.json`，公开目录为 `.local/webui/catalog/rebench-34d5a588.json`。旧路径保持不变。
- 新任务、队列、轨迹、预测和导出保存 `benchmark_snapshot` 与 `case_key=dataset:instance_id`。派发前核对固定版本；新旧基准同题号不能互认补丁或合并分母。
- 求解输入仅使用题目描述和必需接口；不提供标准补丁、隐藏测试或安装命令字段。完整题目只供准备和评测读取。
- `.local/webui/` 以外的新增官方代码位于 `local_setup/webui/vendor/rebench/`，约 298 KB；附 MIT 许可证、上游版本和逐文件哈希。`rebench_harness.py` 在独立子进程中加载这些源码，复用现有 Python，不安装或覆盖宿主环境里的 `swebench==5.0.2`。
- 官方评分、日志解析和评测脚本生成规则保持原样。仅适配无关入口依赖、Windows UTF-8/LF、禁止隐式拉取／构建镜像、只终止所属容器。差异清单在 vendor manifest；生成的测试脚本经过与官方入口等价检查。
- 队列准备环境后记录本地镜像 ID，后续求解和评测检查镜像是否变化。任务输出、报告与清理继续由原任务管理器负责。
- 来源不明的外部 rebench 预测文件不能只靠题号猜归属。JSONL 行或轨迹中需明确记录 `dataset` 或匹配的 `case_key`；官方外部补丁导入的专门确认界面不在本次范围。
