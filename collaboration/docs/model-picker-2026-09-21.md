# 模型对比去重与选择区整理

## 问题与目标

旧页面把运行条件分组直接当作模型入口，“原配置”、自动执行和逐批确认等历史变化形成多行同名项目。选择框放在右半侧，展开后拉长整页。目标是一个实际模型一个入口，并保留不同条件的可追溯性。

## 实现规则

- 按实际模型 ID 组织界面，去掉内部单层 `openai/` 路由前缀；不以“原配置”等显示别名当模型身份，不改模型 ID 大小写或任意供应商路径。
- 同一个模型只显示一行、一个复选框。运行条件放在该行下拉框，保留连接、步数、费用上限、命令确认方式和历史分组。
- 同一模型本次只选一种条件参与历史比较；不删除记录、不改写分组、不将条件未知或参数不同的成绩合并计分。需要比较同型号的不同档案，仍可通过显式同题实验完成。
- 初次沿用后台推荐条件；刷新保留当前选择。切换条件自动勾选对应模型，点击应用后才改变比较结果；JSON/CSV 导出使用已经显示的条件，不使用尚未应用的草稿。
- 模型选择区改为完整宽度的列表，桌面把模型和条件并排，390px 下上下排列；增加模型/连接搜索及空结果提示。
- 修复旧样式的选择器优先级冲突，避免声明为列表后仍被旧的双列网格覆盖。

## 验收

- 真实历史只读核对：10 个条件组对应 5 个实际模型。gpt-5.5 的 5 组条件、grok-4.6 的 2 组条件各归到一个入口，其他三个模型各一行。
- 独立 JS 检查模型身份、原配置别名、同模型多条件、不同实际模型及不修改输入记录。
- 隔离浏览器检查桌面/390px、两个原配置条件合并、条件切换、搜索/无结果、刷新保留及导出与展示一致；无页面脚本错误。
- 12 项结果后端回归通过。impeccable 机械检测无发现，保留浅色和本机字体。
- 未调用模型、未新建环境或安装依赖、未改写正式历史或密钥。改动是静态前端，刷新页面即可加载，不需要重启正式后台。
